# 0014 — Binary releases: release-please tags, dist builds, and a Homebrew formula pushed with a GitHub App

- **Status:** Accepted
- **Date:** 2026-10-29
- **Deciders:** loractl maintainers
- **Same setup as:** laurigates/shore-recon ADR-0016, which shipped 0.1.0 this way

## Context

release-please already versions loractl and creates a GitHub Release per tag,
but the release carries only source. Installing meant cloning and running
`cargo build`, which for a burn-based workspace is a long compile with the
toolchain pinned to `rust-version` 1.92.

## Decision

1. release-please stays the only thing that versions the workspace, writes
   `CHANGELOG.md`, and creates the tag and the GitHub Release.
2. dist 0.32.0 builds on that tag (`release.yml`, generated by `dist generate`
   from `dist-workspace.toml`; not edited by hand). `create-release = false`:
   dist uploads to the release release-please created. Targets are
   `aarch64-apple-darwin` and `x86_64-unknown-linux-gnu`, with a shell
   installer and a Homebrew formula.
3. Only the CLI is released. `loractl-cli` ships the `loractl` binary as the
   `loractl` formula; `loractl-api` sets `dist = false`. The build uses the
   default features (ndarray, offline), so GPU backends still need a source
   build with `--features wgpu` and the like.
4. The formula is pushed to `laurigates/homebrew-tap` by a custom dist publish
   job, `.github/workflows/publish-homebrew.yml`
   (`publish-jobs = ["./publish-homebrew"]`). It mints a short-lived token from
   the `laurigates-homebrew-tap` GitHub App (`vars.HOMEBREW_TAP_APP_ID`,
   `secrets.HOMEBREW_TAP_PRIVATE_KEY`), whose only access is Contents
   read/write on the tap. dist's built-in homebrew job would need a static
   `HOMEBREW_TAP_TOKEN` secret instead.

## Consequences

- The repository needs the homebrew-tap App credentials (gitops
  `homebrew_tap = true`) before the first release that includes `release.yml`;
  without them the publish job fails at token minting after the binaries are
  already uploaded.
- `dist generate` warns that the tap is set but the built-in homebrew job is
  disabled. That is expected: the custom job replaces it.
- Release artifacts are named after the package, `loractl-cli-<target>.tar.xz`;
  the installed binary and the formula are both `loractl`.
